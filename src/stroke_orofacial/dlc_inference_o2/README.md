# DLC Inference (O2)

This submodule runs **only on HMS O2** with GPU access. It is not part of the
local analysis pipeline. It submits DLC inference jobs and copies outputs to
the MICROSCOPE server. The local pipeline consumes those outputs read-only.

Ported from `20251112_DLC_batch_video_analysis_O2.ipynb` (canonical per Rule 1).

## Prerequisites

1. **SSH key auth to O2** (recommended). One-time setup:
   ```bash
   ssh-keygen -t ed25519  # if you don't have a key yet
   ssh-copy-id <username>@o2.hms.harvard.edu
   ```
   If not set up, you'll need to enter your password + DUO push interactively.

2. **DLC conda env on O2.** The env `deeplabcut` must be available:
   ```bash
   module load conda/miniforge3/24.11.3-0
   conda activate deeplabcut
   ```

3. **DLC project files** staged on O2 scratch:
   ```
   /n/scratch/users/<initial>/<username>/dlc_cfg/DLC_train_config/
   ```
   Rsync from MICROSCOPE:
   ```bash
   rsync -avh /n/files/Neurobio/MICROSCOPE/Priya/DeepLabCut/DLC_train_config/ \
     /n/scratch/users/<initial>/<username>/dlc_cfg/DLC_train_config/
   ```

## Workflow

Use `notebooks/10_dlc_inference.ipynb` as the day-to-day driver. The notebook:
- Takes USER INPUTS (animals, dates, username)
- Generates all paths, YAML configs, scripts, and shell commands
- Pure local actions execute directly in the notebook
- SSH/rsync/sbatch commands are printed for you to paste into your terminal

### Step-by-step:

1. **Open the notebook** and set USER INPUTS (animals, dates, username).

2. **Generate and upload scripts** to O2:
   - `run_dlc_batch.py` — the inference runner
   - `video_selection.yaml` — animal/date include/exclude config
   - The notebook prints the rsync/scp commands to upload these.

3. **Stage videos** from MICROSCOPE camera tree to O2 scratch:
   ```bash
   rsync -avh --partial --inplace --update \
     /n/files/.../camera/<DATE>/<ANIMAL>/ \
     /n/scratch/.../dlc_in/<DATE>/<ANIMAL>/
   ```

4. **Submit the SBATCH job:**
   ```bash
   sbatch /n/scratch/.../dlc_code/run_dlc.sbatch
   ```
   Resources: 1 GPU, 10 CPUs, 30G RAM, 9.5 hours.

5. **Monitor:**
   ```bash
   squeue -u <username>
   tail -f /n/scratch/.../logs/dlc_<JOBID>.out
   ```

6. **Rename outputs** (snapshot-best-60 → snapshot_060):
   ```bash
   python3 -c '...'  # command generated by notebook
   ```

7. **Copy to MICROSCOPE** (two-stage recommended):
   ```bash
   # Stage 1: O2 scratch → /n/data1
   rsync -avh ... /dlc_out/ /n/data1/.../O2_staging/
   # Stage 2: /n/data1 → MICROSCOPE
   rsync -avh ... /O2_staging/ <user>@transfer:/.../O2_analysis/
   ```

## Resource Limits

| Resource | Value | Notes |
|----------|-------|-------|
| Partition | `gpu` | O2 GPU partition |
| GPU | 1 | Single GPU |
| CPUs | 10 | I/O + preprocessing |
| Memory | 30G | Safe with batchsize=1 |
| Time | 9:30:00 | ~3 hours per video |
| Excluded | compute-g-16-[254-255] | Known problematic nodes |

## DLC Parameters

| Parameter | Value | Notes |
|-----------|-------|-------|
| shuffle | 5 | Model shuffle index |
| trainingsetindex | 0 | Training set |
| batchsize | 1 | Conservative (prevents OOM) |
| gputouse | 0 | Single GPU (CUDA_VISIBLE_DEVICES=0) |
| allow_growth | true | TensorFlow GPU memory auto-scaling |
| video_glob | `video2_*.avi` | Camera 2 only |
| skip_if_exists | true | Don't reprocess existing outputs |

## Batch Size Tuning (optional)

The `batchsize_scout.py` script (generated by the notebook) tests batch sizes
`[128, 64, 32, 16, 8, 4, 1]` on a 10-second clip and reports GPU utilization
+ wall time. Currently locked to `batchsize=1` for safety.

## Troubleshooting

- **OOM errors:** Reduce `batchsize` (already at 1 by default).
- **Node failures:** Add failing nodes to `exclude_nodes` in
  `configs/defaults.yaml`.
- **Missing videos:** Check the selection YAML includes the right dates.
- **Rsync failures:** Verify the transfer node SSH ControlMaster is active,
  or use interactive password + DUO.
- **Stale outputs:** Use `--skip_if_exists` to avoid reprocessing. To force
  reprocessing, delete the existing H5/CSV in `dlc_out/<ANIMAL>/`.

## Security

- **Never** pass passwords via `sshpass`, environment variables, or files.
- **Never** store credentials in config, commits, or Claude Code sessions.
- Use SSH key auth (preferred) or interactive password entry at the terminal.
